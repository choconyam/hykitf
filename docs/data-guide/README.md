# 자료 정리 방법

사람이 원본을 이해하고 확인하려고 읽는 문서를 이 폴더에 모은다. 자료마다 .md로 두고 PLAN 2절에서 연결한다. 구현·계산·검사에는 원본 또는 분리한 테스트 입력을 쓴다.

## 자동으로 정리할 때
메인만 작업 폴더에서 make_data_guide.py를 실행한다(자료 담당은 실행하지 않고 결과만 읽는다). Python 3.8 이상 기본 기능만 쓰며 추가 설치는 없다. data는 실제 원본 위치로 바꾼다. 원본이 여러 곳이면 --source를 반복한다.

```bash
python3 make_data_guide.py --source data --inventory-only
python3 make_data_guide.py --source data --mask-column 이메일 --mask-column 이름
python3 make_data_guide.py --source data/master --list-only data/trace
```

마지막 명령은 센서 기록처럼 큰 시계열 폴더(data/trace)를 목록과 머리글로만 남기고, 나머지(data/master)만 표로 만드는 예다.

- 첫 명령은 원본 파일 목록과 CSV 구조를 확인한다. 다음 명령은 민감한 열을 가리고 표를 만든다. 민감한 열이 없음을 확인했으면 --mask-column을 생략한다. 자동으로 모든 개인정보를 찾아주는 도구는 아니다.
- _generated/INDEX.md와 manifest.json에서 파일별 상태·확인 범위·생성 표 링크를 본다. 이 폴더에는 make_data_guide.py만 쓴다. 다른 파일을 넣으면 다음 실행이 멈춘다.
- 다른 코드로 만든 전체 표(엑셀 시트·JSON·로그, 설정이 다른 CSV, 범위를 정한 큰 자료)는 그 자료를 맡은 쪽(자료 담당, 없으면 메인)이 docs/data-guide/_extra/에 두고 만든 명령을 적는다. CSV처럼 맨 위에 글을 넣으면 깨지는 파일은 같은 이름에 .md를 붙인 설명 파일(예: summary.csv.md)에 적는다. trace_tools.py summarize는 이 설명 파일을 자동으로 만든다. 자료별 .md(두 폴더 밖)에는 자료 담당이 쉬운 설명·메모를 쓰고 표를 연결한다. 자료 담당이 없으면 메인이 살펴본 내용을 넘겨받아 문서 담당이 쓴다.
- CSV만 표로 만든다. 다른 형식은 목록에 남기므로 별도 방법으로 읽는다. 기본은 첫 기록이 열 이름인 CSV다. 첫 줄이 열 이름이 아닌 CSV는 첫 기록이 열 이름으로 INDEX에 남으므로, 실행 전에 첫 줄을 코드로 확인하고 그런 파일은 --source에서 빼고 _extra/에 따로 옮긴다. 인코딩은 파일마다 UTF-8을 먼저 쓰고, 안 되면 CP949(한글 엑셀에서 저장한 CSV)로 읽어 INDEX에 적는다. CP949로 읽은 파일은 글자가 깨지지 않았는지 확인한다. 다른 인코딩이면 --encoding, 구분자가 다르면 --delimiter를 지정한다. 값의 형식은 자동 변환하지 않는다. 구분자와 직접 지정한 인코딩은 한 실행에 하나만 쓰므로, 설정이 다른 자료가 섞이면 별도 추출이 필요하다.
- 이름이 빈 열은 (이름 없음 1)처럼, 같은 이름이 여러 번 나오는 열은 그대로 표시하고 INDEX의 확인할 점에 적는다. 같은 이름의 열을 --mask-column으로 가리면 그 이름의 열이 모두 가려진다. 빈 줄은 기록으로 세지 않고 개수를 적는다. 열 수가 머리글과 다른 행이나 제어 문자가 있으면 그 파일은 표를 만들지 않고 이유를 남기므로, _extra/에 따로 옮긴다.
- --source로 직접 지정한 폴더는 링크이거나 analysis·tests·out·logs여도 읽는다. 폴더를 훑다가 만난 링크와 작업 폴더 바로 아래 analysis·tests·out·logs, 키트 문서, docs/data-guide/, docs/guide/는 뺀다.
- 기본 한도는 CSV당 10,000행과 10 MiB다. 초과하면 표를 만들지 않고 이유를 남긴다. 필요한 범위·시간을 확인한 뒤 --max-rows 또는 --max-bytes로 조정한다. 표는 1,000행씩 나눈다.
- 입력을 바꾸거나 자료가 추가되면 정리할 원본 경로 전체와 같은 옵션으로 다시 실행한다(이전 명령은 INDEX의 '실행' 줄). 결과를 누적하지 않고 이번에 지정한 원본으로 새로 만든다. 성공적으로 갱신된 INDEX에 연결된 표가 이번 실행 결과다. 예전 표는 도구가 생성한 그대로인 경우에만 정리한다. 자동 생성 파일을 손으로 고치면 덮어쓰지 않고 중단하므로, 이때 남은 INDEX를 새 결과라고 쓰지 않는다.
- 오류·한도 초과는 실패로, 미지원 형식은 미확인으로 남긴다. 성공 종료만으로 모든 자료를 읽었다고 쓰지 않는다. 변환 확인은 값을 맞게 옮겼다는 뜻이며, 자료 의미나 과제 결과의 정답을 보장하지 않는다.

## 자료마다 남길 내용
- 원본 위치, 옮긴 범위와 빠진 부분, 만든 명령을 맨 위에 적는다.
- 무슨 자료인지, 한 항목과 각 값의 쉬운 뜻·단위, 빈 값·이상한 값의 종류와 개수, 쓰이는 요구사항(R번호)을 적는다. 뜻을 확정하지 못했으면 추정과 질문을 표시한다.
- 다른 자료와의 연결을 적는다. 표는 이어지는 열과 맞는·안 맞는 행 수 및 확인 명령, 문서·이미지는 서로 가리키는 위치나 식별값을 쓴다. 아직 검사하지 않은 연결은 후보로 둔다.
- 비교 조건·계산 결과·해석은 분석했을 때 analysis/RESULTS.md에 두고 연결한다. PLAN에는 기준이나 구현을 바꾸는 발견만 요약한다.

## 형식별 확인과 정리
- CSV·엑셀: 시트, 행·열 수, 열 이름, 앞 5행, 빈 값과 중복을 코드로 확인한다. 쉬운 설명에서 전체 행을 담은 표로 연결한다. CSV는 make_data_guide.py를 쓰고, 엑셀은 별도 방법으로 시트마다 문서를 두며 숨은 시트·병합 셀·수식도 표시한다.
- PDF·워드·텍스트: 쪽 수, 제목·목차, 표 위치, 글자를 뽑을 수 있는지 확인한다. 원문 순서대로 제목·문단·표를 옮기고 쪽·절을 붙인다. 조건과 예외를 빠뜨리지 않는다.
- 이미지: 개수와 내용, 글자를 읽어야 하는지 확인한다. 원본을 상대 경로로 넣고 무엇을 담았는지 적는다.
- 장비 센서 기록(시계열): 웨이퍼·작업 하나에 수천 행씩 쌓이는 자료는 전체를 옮기지 않는다. 한 행의 뜻(시각·센서·값과 단위), 기록 간격, 식별 열(장비·챔버·웨이퍼·스텝)을 적는다. 그리고 단위(웨이퍼·스텝)별 요약표를 `python3 trace_tools.py summarize ... --out docs/data-guide/_extra/<이름>.csv`로 만들고, 정상·이상 대표 사례 몇 개의 구간은 코드로 잘라 _extra/에 두고, 그림은 `trace_tools.py plot`으로 out/fig/에 그려 연결한다. 센서 기록 파일은 행 수와 상관없이 make_data_guide.py로 표를 만들지 않는다. --source 대신 --list-only로 넣어 목록과 머리글만 남긴다.
- JSON·로그: 항목의 뜻과 한 기록의 단위를 설명하고 전부 옮긴다. 큰 자료는 아래 범위 확인 규칙을 따른다. 다른 형식은 여는 방법과 확인한 내용만 적는다. 읽지 못한 부분을 남긴다.

## 변환과 재실행
- 값과 행을 옮기는 일은 코드로 한다. 앞자리 0, 날짜, 빈 값과 0을 바꾸지 않는다. 계산·해석·가린 값은 따로 표시한다.
- 옮긴 행 수와 값이 원본과 맞는지 코드로 대조한다. 표에서 줄바꿈·따옴표·구분 기호 때문에 값이 잘리거나 열이 밀리지 않았는지도 확인한다.
- 1,000행이 넘으면 1,000행씩 나눈다. 1만 행이 넘으면 크기를 알리고 옮길 범위를 사람과 정한다. 큰 비표 자료도 크기와 예상 시간을 먼저 알린다. 만든 문서를 AI가 다시 통째로 읽지 않는다.
- 자동으로 읽은 글자와 읽지 못한 부분은 미확인으로 표시한다. 개인정보와 비밀값은 가린 뒤 가렸다고 적는다.
- 자동 생성 표는 _generated/(make_data_guide.py)와 _extra/(다른 변환 코드), 설명·메모는 그 밖의 자료별 문서에 둔다. 다시 실행할 때 설명·메모를 덮어쓰지 않는다. 설명을 쓰는 쪽은 생성 결과의 상태와 범위를 확인한 뒤 설명 문서에 연결한다.
- 문서를 만들거나 변환 검사가 통과한 것만으로 사람이 읽거나 검수했다고 적지 않는다.
