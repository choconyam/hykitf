# 작업 계획

> 전체 방향을 판단할 핵심만 짧게 적고, 자세한 자료·분석·작업 과정은 해당 문서로 연결한다.

## 1. 무엇을 해야 하나
- **현재 상황:** 쓰는 사람, 지금 방식, 해결할 문제. 근거(원문 위치·Q번호)를 붙인다.
- **요구사항:** 원문에 있는 것만 R1, R2…로 적는다. 줄마다 원문 위치와 짧은 인용을 붙인다.
- **처음 보는 용어:** 원문 용어 → 쉬운 뜻. 원문에 뜻이 없으면 '추정'을 붙이고 담당자 질문 후보로 둔다.
- **범위 밖:** 상위 요구사항과 연결되지 않거나 합의에서 제외된 기능.
- **제출물:** 형식, 제출·실행 조건, 근거.

## 2. 자료 색인
원본만 행으로 적고, 구조가 같은 파일 여럿은 묶어 한 행으로 적는다. 키트 문서, 테스트 자료, 결과물, 사람용 정리 문서는 행으로 적지 않는다.

| 원본(상대 링크) | 사람용 정리(상대 링크) | 형식·규모 | 내용 한 줄 | 쓰는 곳(R번호) | 확인 상태·읽지 못함·충돌 |
|---|---|---|---|---|---|

자료별 뜻·단위·연결·이상한 값과 원본 표는 해당 자료 문서에 둔다. 작성 방법은 [자료 정리 방법](data-guide/README.md)을 따른다. 여기에는 반복하지 않는다.

**계획에 반영할 분석 결과 (3개 이내)**
집계·비교 표와 조건은 분석을 했을 때 `analysis/RESULTS.md`에 정리한다. 여기에는 기준이나 구현에 영향을 주는 발견만 적는다. 원인을 찾는 과제면 현상 정의·가설·확인 결과는 [원인 분석](CAUSES.md)에 두고 여기에는 결론만 적는다.
- `[사실/가설]` 발견 → 기준·구현에 미치는 영향 → 확인할 점과 분석 근거 링크

## 4. 세부 조건과 성공 기준
큰 요구의 세부 기준을 자료에서 찾아 후보로 적는다. 담당자 답과 사람의 판단을 반영해 채택 여부를 표시한다. 실제 질문과 답은 [담당자 질문과 답](QUESTIONS.md)에 둔다.
- **바꿀 수 있는 것:** 상위 R번호 / 우리가 정할 항목 / 자료로 알 수 있는 범위 / 더 물을 점
- **필수 조건:** 상위 R번호 / 지켜야 할 조건 / 근거 / 검사 방법. 확인 중인 조건은 후보로 표시한다.
- **개선 기준:** 상위 R번호 / 후보·채택·보류 / 무엇을 얼마나 개선할지 / 이유와 근거 / 비교할 기존 방식·기준안과 검사 방법. 목표 수치의 근거가 없으면 미확정으로 적는다.
- **우선순위:** 기준이 충돌하면 어떤 쪽을 우선할지와 그 이유를 적는다.
- **전제:** `[사실 / 가정 / 미확정]` 조건 → 구현에서 처리할 방법

## 5. 범위와 구현 순서
- **범위:** 할 것(R번호) / 제외 / 보류(근거 없음, 예상 시간)
- **만들 형태와 이유:**
- **큰 그림:** 입력 → 핵심 처리 → 결과
- **구현 순서:** 작업마다 상위 R번호, 적용할 조건·기준, 완료 조건과 검사 방법을 붙인다. 최소 기능에 드는 작업에는 `[최소]`를 붙인다.
- **검사 명령:** `___`
- **작은 예시:** 입력 → 기대 결과(사람이 먼저 정함) → 근거 → 실제 결과
