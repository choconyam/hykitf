# 예측·판별 안내 (결과를 맞히거나 결과를 가르는 조건을 찾을 때)

> 메인이 시작하기 전에 끝까지 읽는다. AGENTS.md가 우선한다. 불량 여부·수율·측정값 같은 결과 열이 있고, 그 결과를 미리 맞히거나(불량 예측, 가상 계측, 고장 시점 예측) 결과를 가르는 센서·조건·장비를 찾는 과제에 쓴다.
> 놓침·오경보와 '진짜 이상'의 정의는 [원인 분석 안내](causes.md)를 따르고, 찾은 조건을 알람 규칙으로 만들 때는 [관리 기준 안내](spc.md)도 읽는다. CAUSES.md와 RESULTS.md에 적는 일은 메인이 결과 파일 경로와 명령을 문서 담당에게 넘겨 맡긴다. 문서 담당이 없을 때만 메인이 직접 쓴다.

- 먼저 판단 단위(웨이퍼·로트·작업 하나)를 정하고, 한 행이 그 단위 하나인 표를 만든다. 센서 기록은 `python3 trace_tools.py summarize`의 스텝별 요약값(평균·p95·최대 등)을 열로 펴고, 결과 열은 식별 열로 붙인다. 붙지 않은 행과 결과가 없는 행의 수를 적는다.
- 열마다 '판단하는 시점에 이미 알 수 있는 값인가'를 확인한다. 결과가 나온 뒤에야 생기는 값, 결과에서 계산된 값, 판단 시점보다 미래의 값은 입력에서 뺀다. 뺀 열과 이유를 적는다. 결과와 거의 완벽하게 맞는 열이 있으면 이런 열이 아닌지 먼저 의심한다.
- 자료는 시간 순서로 앞(정하는 기간)과 뒤(확인하는 기간)로 나눈다. 무작위로 섞지 않는다. 같은 로트나 같은 날의 행이 양쪽에 걸치지 않게 한다. 확인 기간의 숫자를 보고 방법을 다시 고쳤으면 그렇게 적는다.
- 가장 단순한 기준부터 숫자를 낸다: 전부 정상이라고 답하기(숫자를 맞히는 과제면 평균이나 직전 값으로 답하기), 가장 잘 가르는 열 하나의 문턱값. 모델은 확인 기간에서 이 기준보다 나을 때만 쓰고, 얼마나 나은지 같은 표에 적는다.
- 불량이 드문 자료에서는 맞힌 비율(정확도)로 평가하지 않는다. 전부 정상이라고 답해도 높게 나오기 때문이다. 확인 기간의 놓침·오경보 건수, 불량 중 잡은 비율(재현율), 불량이라고 한 것 중 실제 불량의 비율(정밀도)을 적는다. 문턱은 놓침과 오경보 중 무엇이 더 큰 손해인지에 따라 정하고 근거를 적는다.
- 숫자를 맞히는 과제(가상 계측 등)는 오차의 크기(평균 절대 오차)를 단순한 기준의 오차와 견주고, 규격 폭에 비해 얼마나 큰지 적는다.
- 열이 많으면(수십~수백 개) 먼저 줄인다. 값이 하나뿐인 열, 대부분 빈 열, 서로 거의 같은 열을 빼고 뺀 수를 적는다. 남은 열은 하나씩 결과를 얼마나 잘 가르는지(정상과 불량의 평균 차이를 흩어짐으로 나눈 값이나 AUC)로 순위를 매긴다. 수백 개를 훑으면 우연히 잘 맞는 열이 나오므로 상위 후보는 확인 기간에서 다시 보고, 장비 지식으로 말이 되는지는 질문 후보나 가정으로 올린다.
- 불량이 어디서 왔는지 찾을 때는 지나간 경로를 표로 본다. 장비·챔버·스텝·날짜마다 지나간 수, 불량 수, 불량률을 내고 전체 불량률과 견준다. 지나간 수가 적은 칸은 표시하고, 한 칸만 높은지, 같은 로트가 몰려 지나가서 여러 칸이 함께 높아 보이는지 확인한다.
- 빈 값은 종류를 나눈다(측정하지 않음, 센서 끊김, 해당 없음). 0이나 평균으로 채웠으면 채운 방법과 개수를 적고, 채우는 값은 정하는 기간의 자료로만 계산한다.
- 모델은 설명할 수 있는 단순한 것부터 쓴다(문턱 규칙 몇 개, 얕은 결정 트리, 선형 모델). 이미 설치된 패키지만 쓰고 새 설치는 먼저 묻는다. 난수 씨앗을 고정해 다시 돌려도 같은 숫자가 나오게 한다. 결과에 크게 영향을 준 입력 3~5개와 방향(값이 크면 불량이 는다 등)을 사람이 자기 말로 설명할 수 있게 적는다.
- 결과를 어떻게 쓸지도 적는다: 예측이 틀렸을 때의 대응, 다시 맞춰야 하는 때(점검·부품 교체 뒤, 레시피 변경 뒤, 확인 기간의 성능이 떨어질 때).
