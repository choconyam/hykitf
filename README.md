# hykitf

AI 코딩 도구에게 과제를 맡길 때 쓰는 작업 지침, 문서 양식, 자료 분석 도구다. 과제 안내와 현장에서 받은 환경 안내가 이 키트보다 우선한다. 외부 자료를 쓸 수 없는 환경이면 쓰지 않는다.

미리 준비한 자료를 써도 되는지는 환경 안내로 먼저 확인한다.

작업 폴더의 Bash에서 실행한다. 받는 위치(/tmp/kit)는 작업 폴더 밖이면 어디든 된다. Bash나 git이 없으면 ZIP으로 받거나 다른 방법으로 옮긴 뒤, apply.sh의 파일 목록에 있는 파일을 같은 경로로 작업 폴더에 복사한다. 이미 있는 파일은 덮어쓰지 않는다.

```bash
GIT_TERMINAL_PROMPT=0 git clone --depth 1 https://github.com/choconyam/hykitf /tmp/kit
bash /tmp/kit/apply.sh
```

기존 AGENTS.md 때문에 키트 규칙이 적용되지 않았다는 안내가 나오면, 원래 지침을 보존하고 출력된 덧붙이기 명령으로 키트 지침을 아래에 추가한다.
적용 후 AI 도구를 다시 시작할 수 있으면 작업 폴더에서 다시 시작한다. 다시 시작할 수 없거나 AGENTS.md를 자동으로 읽지 않는 도구면 첫 요청 맨 앞에 'AGENTS.md를 먼저 끝까지 읽어'를 붙인다.
키트를 작업 폴더 안에 받았다면 첫 요청 전에 그 폴더를 지운다(/tmp/kit은 그대로 둬도 된다).

첫 요청은 이렇게 하고, 그 아래에 apply.sh 출력을 그대로 붙인다. 현장 환경 안내가 종이나 화면으로만 있으면 필요한 부분(쓸 수 있는 도구, 금지 사항, 제출 방법, 평가 기준)도 함께 적어 준다.

> 아래 apply.sh 출력에서 '복사함'인 파일만 먼저 커밋해(키트 버전은 마지막 줄). 그다음 AGENTS.md에 따라 과제 안내와 환경 안내, 자료부터 파악해. 적용한 지침, 읽은 안내 파일, 문서 담당과 자료 담당 준비 여부를 짧게 알려줘.

AGENTS.md는 메인(총괄)이 따르는 짧은 지침이고, 일의 종류별 안내는 docs/guide/에 나눠 두었다. 메인이 과제에 맞는 안내만 골라 읽는다.
하위 에이전트를 쓸 수 있는 도구면 메인이 문서 담당 1명을 만들어 문서 갱신을 맡기고, 자료가 여러 묶음이면 묶음마다 자료 담당을 만들어 동시에 살펴보게 한 뒤 보고를 직접 다시 확인해 합친다. 별도로 서브에이전트를 만들라고 요청할 필요는 없다. STATUS는 메인이 바로 고친다. 기능이 제공되지 않으면 이유를 알리고 메인이 직접 한다.
처음 파악한 내용을 확인한 뒤 `진행`이라고 답한다. 이후 문서 갱신은 메인이 맡기므로 따로 요청하지 않아도 된다.

자료 파악 때 메인이 make_data_guide.py로 파일 목록과 CSV 표를 만든다. Python 3 기본 기능만 쓰며, 표는 docs/data-guide/_generated/에 둔다. 자세한 사용법은 [자료 정리 방법](docs/data-guide/README.md)에 있다. 센서 기록(시계열)이 있으면 trace_tools.py로 웨이퍼×스텝 같은 묶음별 요약표와 그래프(out/fig/, SVG)를 만든다. 관리 기준(SPC 규칙)을 만드는 과제면 같은 도구의 spc로 관리 한계와 규칙별 신호를 계산한다. 과제 검사 도구 check.py는 실제 문제와 성공 기준을 정한 뒤 만든다.

키트 커밋 형식은 AGENTS.md 7절에 있다.
