# 작업로그

> 문서 담당은 메인이 전달한 실제 작업·협업 근거를 시간순으로 한 줄씩 추가한다. 줄 앞에 사건 시각을 KST(HH:MM)로 붙이고, 파일 이름·명령·숫자 중 하나 이상을 넣는다. 명령이나 재시도마다 적지 않는다.

- `HH:MM [작업] 한 일과 이유 → 바꾼 파일 → 검사 결과(PASS n/m)`: 커밋할 때
- `HH:MM [결정] 고른 방법 → 이유 → 버린 대안과 이유(없으면 '검토 안 함') → 정한 사람(사람/AI)`: 방향을 바꿀 때
- `HH:MM [사람] AI가 낸 것 → 사람이 확인한 방법·근거 → 판단·보완 지시와 이유 → 후속 확인 결과`: 중요한 검수·보완을 했을 때
- `HH:MM [문제] 증상 → 원인·근거 → 해결 방법 → 실제 수정·확인 결과와 남은 점`: 중요한 문제를 조사·해결했을 때
- 사람이 맡긴 일·선택·보완·검수와 AI의 조사·제안·구현을 구분한다. 실제로 한 것만 쓰고, 같은 사건은 한 기록에 모아 관련 [작업]·[결정]을 연결한다.
- [사람]·[문제]도 작업 중 여기에 남긴다. 과제가 AI와 협업한 기록 문서를 요구하면 [문서 담당 안내](guide/docs-agent.md)에 따라 최소 기능이 돈 뒤 한 번 정리하고, 이후 중요한 기록은 덧붙이고, 제출 전에는 빠진 것만 채운다. 그 문서의 작성자·작성 시점 지침이 우선이며, 사람이 직접 쓰는 경우 참고할 사실과 기록 위치만 알려 준다.
- 사람이 이해·판단·확인한 범위는 실제 대화나 사람이 알려 준 결과에 근거한다. AI의 제안을 사람의 결정으로 바꾸거나 승인만으로 검수 완료라고 쓰지 않는다.
- 대표 사례는 하위 줄로 붙인다: 근거(R번호·Q번호), 입력, 실행 명령, 기대(사람이 먼저 정한 값) / 실제.
- 결정만 내린 것을 완료로 적지 않는다. 안 고친 것·맞는지 모르는 것·안 돌려 본 것은 그대로 적는다.
