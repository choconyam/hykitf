# 자료 담당 안내 (자료 한 묶음을 살펴보는 하위 에이전트)

> 자료 담당이 일을 시작할 때 끝까지 읽는다. AGENTS.md의 '# 작업 원칙' 바로 아래 인용문과 0절(범위와 보고)·5절(원본과 보안)을 지킨다. 거기서 사람에게 묻거나 알리라는 것은 메인에게 보고하는 것으로 읽는다. 메인이 맡긴 묶음 하나만 본다. 다른 에이전트를 만들지 않고, 사람에게 직접 묻지 않으며, 막히면 메인에게 보고한다.
> 자료 담당이 없어 메인이 직접 살펴볼 때도 이 안내를 따른다. 다만 메인은 docs/data-guide/<묶음 이름>.md를 직접 쓰지 않고 보고 내용을 문서 담당에게 넘긴다(문서 담당도 없으면 메인이 쓴다).

## 메인에게서 받는 것
- 맡은 원본 경로(묶음 이름), 이 자료가 과제에서 쓰일 곳(R번호와 메인이 궁금한 점), 다른 묶음의 식별 열 이름(있으면), 가린 열(--mask-column)과 확인 범위, 쓸 파일 이름.

## 하는 일
1. 원본은 읽기만 한다. 크기·형식·행 수부터 보고 내용은 코드로 확인한다. 터미널에 파일을 통째로 출력하지 않는다.
2. [자료 정리 방법](../data-guide/README.md)의 '자료마다 남길 내용'과 '형식별 확인과 정리'를 따라 자료 설명을 쓴다: 한 행의 뜻, 열마다 뜻과 단위(확정·추정을 표시), 기간과 값의 범위, 빈 값·중복·이상한 값의 종류와 개수, 식별 열과 다른 자료와 이어질 열. 가린 열과 개인정보로 보이는 열은 값 예시를 적지 않는다.
3. 센서 기록(시계열)은 통째로 옮기지 않는다. `python3 trace_tools.py summarize`로 묶음별 요약표를 만들어 기록 간격, 스텝 구성, 스텝별 평소 범위를 적고, 대표 그림 1~2개를 `trace_tools.py plot`으로 그린다. 옵션은 `-h`로 확인한다.
4. 눈에 띄는 것을 3개 이내로 적는다. 예: 값이 갑자기 바뀌는 시점, 한 값에 붙은 구간, 특정 장비나 기간에만 있는 것, 다른 열과 맞지 않는 값. 숫자와 위치만 적고 원인은 단정하지 않는다. 원인 판단과 자료를 서로 잇는 분석은 메인이 한다.
5. 숫자는 모두 코드로 얻고 재현 명령을 붙인다. 열의 뜻을 자료만으로 정할 수 없으면 추정으로 표시하고 담당자에게 물을 것으로 올린다.

## 쓰는 파일 (이 밖의 파일은 만들거나 고치지 않는다)
- docs/data-guide/<묶음 이름>.md: 자료 설명
- docs/data-guide/_extra/<묶음 이름>_*.csv와 옆의 .md: 코드로 만든 요약표
- analysis/explore_<묶음 이름>.py: 살펴볼 때 쓴 코드
- out/fig/<묶음 이름>_*.svg: 그림
- make_data_guide.py는 실행하지 않는다(docs/data-guide/_generated/는 메인만 갱신한다). 파일 목록과 열 이름은 _generated/INDEX.md에서 본다.

## 메인에게 하는 보고 (15줄 이내)
- 자료: 파일 수, 행 수, 기간, 한 행의 뜻
- 식별 열과 다른 자료와 이어질 열(값 예시 1개씩)
- 뜻이 불확실한 열과 담당자에게 물을 것
- 빈 값·중복·이상한 값: 종류와 개수
- 눈에 띄는 것 3개 이내: 숫자, 위치(파일·식별값·시각), 재현 명령
- 확인하지 못한 것
- 만든 파일 경로
- 메인이 다시 돌려 확인할 명령 1개와 그 명령에서 나와야 하는 숫자(행 수나 개수를 세는 명령처럼 파일을 덮어쓰지 않는 것)
